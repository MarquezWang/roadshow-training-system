# Transcription Policy

## 背景

路演训练系统后续将使用"路演者实际讲了什么"作为 QA 评委提问、路演表现分析和最终报告评分的重要依据。为避免用户事后大幅修改转写文本导致评分失真，正式评分流程应以自动转写结果作为主要依据。

## 当前决策

1. 正式评分依据使用自动转写文本。
2. 手动转写功能仅作为历史/调试能力暂存，后续将从前端正式训练流程中移除。
3. 用户不应通过自由编辑转写文本来影响正式评分结果。
4. QA 问题生成和 report 分析默认使用 PITCH 阶段录音对应的自动转写文本。
5. 当前阶段先完成"整段 PITCH 录音 → 自动转写 → QA / report 使用 transcript"的最小闭环。
6. 暂不引入用户手动修改作为评分输入。

## 后续方向

1. Pitch 环节建议保留整段录音，而不是按每页切割成多个音频文件。
2. 后续可增加翻页时间轴，记录每一页的展示时间段。
3. 后续可使用带时间戳的转写结果，将讲话内容映射到对应 PPT 页面。
4. 如果用户返回某一页补充讲解，应记录为同一页面的多段讲解，而不是覆盖原讲解。
5. 目录页、封面页、过渡页允许快速带过，不应简单按停留时间过短扣分。
6. QA 环节适合按问题拆分录音和转写，即一个问题对应一段回答音频和一段回答转写。

## 暂不处理

1. 暂不修改 Prisma schema。
2. 暂不删除现有手动转写接口。
3. 暂不改前端 UI。
4. 暂不做页面级分析。
5. 暂不做 QA 回答自动转写。
6. 暂不做多 transcript 版本管理。
